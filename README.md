# Rest

## 핵심 원칙
URL은 동사(행위)가 아니라 명사(자원)을 나타내고, 무엇을 할지는 HTTP 메서드로 표현한다.

## 메서드
GET: 조회
POST: 생성
PUT: 수정(자원 전체 덮어쓰기, 멱등성)
PATCH: 수정(자원의 일부 교체)
DELETE: 삭제

## HTTP 응답 코드
| 구분 | 성공 응답 코드 | 존재하지 않는 자원 | 유효성 검증 실패 |
|---|---|---|---|
| 조회 | 200 | 404 | 400 |
| 수정 | 200 | 404 | 400 |
| 생성 | 201(Created) | _ | 400 |
| 삭제 | 204(No Content) | 404 | 400 |

본 프로젝트에서 삭제 성공 시 200, 본문 meta 필드에 성공을 써준다.

## 예외 및 예외 처리기
각 도메인마다 비즈니스 로직 예외 정의 및 @RestControllerAdvice를 사용해서 예외 처리기를 정의한다.
클라이언트와는 약속을 통해 코드를 열거형 등으로 관리하도록 한다.

## Controller 레이어 OpenAPI Swagger 문서 작성
- Type Annotation
  * @Tag
- Method Annotation
  * @Operation
  * @Parameter

#### @ApiResponses를 사용하지 않는 이유
응답 HTTP 메서드 400, 404, 409를 나열해봤자 실질적인 사용 가치가 크지 않으며 클라이언트에서는 응답 객체의 Meta 필드만 신경쓰면 되므로 제외했다. 
하지만 새로운 예외 타입을 서비스 레이어에서 추가할 때 마다, 컨트롤러의 @ApiResponses에도 함께 추가해줘야 하며, 컨트롤러의 코드도 무거워진다.
다만 @ApiResponses를 사용하지 않았을 때 문제는, POST 작업시 성공했을 때 '201 CREATED'를 반환하지만, 문서에는 200으로 나오는 것이다.
